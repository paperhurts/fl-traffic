# Florida traffic

A live traffic map of Florida (Vite + TypeScript, no framework, MapLibre for the map), with FL511's cameras and events, TomTom's speeds and drive times, and saved routes. A sibling of waterways.paperhurts.dev: same tokens, fonts, and chip-and-card layout, but its own site, since that one is about water. See README.md for the data method.

## Commands
- `npm run dev`: dev server on **5191** (preview on 4191), pinned with `strictPort`. Other local projects use 5173/4173, 5180, and 5190/4190.
- `npm test`: Vitest, unit tests in `src/**` plus `tests/` (data checks on `public/data/cameras.json`, the relay, FL511 parsing).
- `npm run build`: `tsc`, then `vite build`.
- `npm run cameras` refetches the camera list; `npm run relay` serves the relay locally on 5291. Behind a proxy (a cloud session), Node's fetch needs `NODE_USE_ENV_PROXY=1`.

## Things that aren't obvious from the code
- **FL511 has no public API.** Its developer pages are gone, and its website's feeds (`/List/GetData/<list>`, `/map/mapIcons/<layer>`, `/map/data/<layer>/<id>`, `/map/Cctv/<image id>`) are what its own pages use. They can change without notice; the camera script and the relay fail loudly rather than publish a short list (`MIN_CAMERAS`, the stale flag). Keep requests to FL511 few: the relay asks at most once a minute, the camera script once a deploy with a pause between pages.
  - The lists page 100 at a time whatever `length` asks for, by a sort that isn't unique, so the camera script fills any camera the list skipped from the map layer's ids.
  - The events list has no positions; each map layer's icon feed does, by id. Rows whose layer isn't in `LAYERS` are dropped.
  - List times ("10/8/26, 4:03 PM") are Eastern for every county, the Panhandle's Central-time ones too (`parseTime`).
  - Construction descriptions carry HTML; `plainText` strips it, and the page escapes every FL511 string anyway (`esc`).
  - A camera site's id (its FL511 link, `fl511.com/map#camera-<id>`) and its image ids (its stills) differ for about 600 sites; `cameras.json` keeps both. Live video needs FL511's sign-in token, so the page links to FL511 for it and never plays it.
- **The relay** (`supabase/functions/fl511/`) is deployed to the waterways journal's Supabase project with `--no-verify-jwt`. `relay.ts` and `parse.ts` use only web APIs, so the tests and `npm run relay` run them in Node; `index.ts` is the Deno entry. It answers CORS only for the origins in `ORIGINS` (or the `ALLOWED_ORIGINS` secret). It also hands the page TomTom's key (`/fl511/config`, from the `TOMTOM_KEY` secret), so the key stays out of the repo and can change without a deploy. Don't commit TomTom keys.
- **Data contracts.** `src/shared/types.ts` defines `cameras.json`; the relay's response types live in `parse.ts` (the function deploys without `src/`) and `types.ts` re-exports them. Change a shape on both sides and in the tests.
- **TomTom.** Flow tiles are `traffic/map/4/tile/flow/relative0/...`, 512 px, in both themes: `relative0-dark` is too dim on the dark basemap. The key's ramp colors are sampled from real tiles. Passing `thickness` with the `relative0` styles is a 400. Route sections: TomTom gives roadwork of unknown delay `magnitudeOfDelay` 4, the same as closures, so `jamKind` reads the category first. Routing and search count against the key's daily non-tile allowance, so the page only asks when a route opens, every three minutes while it's open, and when a search is submitted (never per keystroke). A flow tile error turns Speeds off rather than retrying.
- **MapLibre 6** has no default export, and finds its worker next to its own module, which Vite moves, so `mapview.ts` hands it one Vite builds (`?worker&url`, `worker.format: "es"`). Missing basemap icons go through `setMissingStyleImageResolver`.
- **Layer order.** The basemap's symbol layers are moved above all its other layers (`basemap()`), so the speeds and the route's line go between the roads and the labels. On a color-scheme change the whole style reloads and `addLayers` puts every layer back from what the page last set. If OpenFreeMap doesn't answer, a blank basemap still shows the cameras and events.
- **Routes** (`src/routes/`): saved in `localStorage` only (`fl-traffic.routes`), so a blocked or cleared storage just means none saved. Matching is in `match.ts` (README has the rules). On phones the panel has a fixed height: when it followed its content, the map changed size under a route just fitted to it.
- **Theme.** Colors are CSS custom properties in `src/tokens.css`, read by the map via `cssVar()`. Keep them plain hex/rgba. Event markers differ by shape and glyph as well as color, and cards and the key name them, so nothing rests on color alone.
- **Hosting.** The site lives at `fl-traffic.paperhurts.dev`: a Pages custom domain (set in Settings → Pages, so no CNAME file; Actions deployments ignore one), backed by a CNAME record `fl-traffic` → `paperhurts.github.io` at Namecheap, like waterways. The `paperhurts-dev` topic lists it on the paperhurts.dev homepage. The relay's `ORIGINS` must include wherever the page is served.
  - Link previews: the repo's social preview (Settings → General) only covers github.com links, so the page's `og:image` is the same picture committed as `public/github-social-preview.jpg`. Replace both together, at 1280×640.
- **Deploy.** Pages via Actions on push to main and daily; the daily run refreshes `cameras.json` in the build only, checked by `tests/data.test.ts`, keeping the committed file if FL511 fails. GitHub pauses scheduled workflows in public repos after 60 days without a push.
- **No PII in the repo.** Keep local paths, usernames, emails, and keys out of committed files. The data is FL511's public camera list.
- **Nothing personal on GitHub.** Commits end with the `Co-Authored-By` line only, and PR descriptions with the "Generated with Claude Code" line only, as in waterways: no session links, and nothing about where anyone lives or drives (test routes in PRs use public places).
